## 2. Что сказать (короткие тезисы, по одному предложению)

1. **Архитектура.** Приложение — это фронтенд на React + TypeScript (VKUI, VK Bridge, vk-mini-apps-router) и отдельный сервер на Node.js + Express + SQLite; обмен по REST API в формате JSON.
2. **Почему данные группы не в VK Storage.** У методов `storage.get` / `storage.set` есть параметр `user_id` — переменные привязаны к пользователю, поэтому каждый видел бы только свою копию. В VK Storage остались только личные настройки (подгруппа, показ прошедших пар).
3. **Слой хранения.** Экраны не знают, откуда данные: они вызывают `loadGroupData()` и методы изменения. Внутри — API сервера, VK Storage и localStorage. Если сервер недоступен, приложение автоматически переходит в локальный режим и **не падает**.
4. **Оптимистичное обновление.** Интерфейс обновляется сразу, не дожидаясь сети, затем состояние заменяется ответом сервера. Пользователь не чувствует задержки, данные остаются корректными.
5. **Типобезопасность.** Все типы описаны в `src/types.ts` и используются на обоих концах; компилятор TypeScript поймал 8 несовпадений с API VKUI 8 ещё до запуска.
6. **Тестирование и поставка.** 21 проверка API (`npm test`), проверка типов `tsc`, линтер без предупреждений, сборка Vite, публикация утилитой `vk-miniapps-deploy` с автоматическим обновлением адреса.

## 4. Вероятные вопросы комиссии и ответы

**Почему SQLite, а не PostgreSQL?**
Тот же SQL и та же схема; SQLite выбран, чтобы проект запускался без установки сервера БД. Переход — замена `node:sqlite` на пакет `pg` и правка подключения (~10 строк), схема таблиц и маршруты остаются.

**Что будет, если сервер упадёт?**
Приложение продолжит работать: слой хранения переключится на localStorage, а в настройках появится отметка «локально». Данные не потеряются, но обмен с группой приостановится.

**Как проверяются данные, которые присылает клиент?**
На сервере обязательна проверка обязательных полей, существования предмета и корректности времени (`endTime > startTime`). Тест проверяет, что «мусорные» запросы отклоняются с кодом 400.

**Где слабое место по безопасности?**
Имя автора задания приходит с клиента. В боевом варианте нужно проверять подпись параметров запуска ВКонтакте (`sign`) и брать пользователя из проверенных данных, а также ограничить список источников CORS.

**Почему мини-приложение не пишет в беседу само?**
Мини-приложение не имеет права отправлять сообщения — для этого нужен бот (сообщество + токен + сервер, слушающий события). Реализованный путь — кнопка «Поделиться», которая отправляет ссылку в беседу; бот — следующий этап развития.

**Как масштабировать на несколько групп?**
Добавить таблицу `groups` и поле `group_id` во все таблицы, а в API — параметр группы. Модель данных это уже позволяет, так как все сущности связаны через идентификаторы.
