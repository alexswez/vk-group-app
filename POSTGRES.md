# Вариант C: PostgreSQL в интернете + хостинг сервера

Инструкция для студента. После этих шагов приложение заработает у **всей группы**: расписание и
задания будут общими, данные сохранятся при перезапусках, и всё это без твоего включённого
компьютера.

---

## Как это будет устроено

```
Телефон одногруппника
        │
        ▼
vk.com/app54822849  ──►  Хостинг ВКонтакте (только статика: HTML, JS, CSS)
        │
        │  запросы к API по HTTPS
        ▼
Render (бесплатный хостинг Node.js)  ──►  Neon (бесплатный PostgreSQL)
        наше Express-приложение                таблицы: subjects, lessons, tasks, meta
```

Код сервера **уже готов** к этому: он сам определяет режим. Если задана переменная окружения
`DATABASE_URL` — работает PostgreSQL, если нет — локальный SQLite. Поэтому твой ноутбук
продолжит работать без всякой установки.

## Шаг 1. Создать бесплатную базу PostgreSQL (Neon)

1. Открой https://neon.tech и зарегистрируйся (можно через GitHub или Google). Карта не нужна.
2. Нажми **Create project**. Имя — любое, например `vk-group-app`. Регион — ближайший к тебе
   (например, Frankfurt).
3. После создания откроется окно **Connection string**. Скопируй строку вида:

   ```
   postgresql://neondb_owner:ПАРОЛЬ@ep-xxx-yyy.eu-central-1.aws.neon.tech/neondb?sslmode=require
   ```

   ⚠️ Параметр `sslmode=require` в конце обязателен: облачные базы принимают только
   защищённое соединение. Сохрани строку — она понадобится на шаге 3.
4. Пароль больше нигде не показывается — если потеряешь, в Neon его можно сбросить.

**Никому не пересылай эту строку**: в ней пароль от базы. Если понадобится помощь — присылай её
без пароля (замени на `***`), я подскажу по формату.

## Шаг 3. Развернуть сервер на Render

1. Открой https://render.com и войди через GitHub.
2. **New → Blueprint** (или **New → Web Service**, если Blueprint не находится).
3. Подключи репозиторий `vk-group-app`. Render сам прочитает файл `render.yaml` из проекта —
   в нём уже прописаны нужные команды:
   - Root Directory: `server`
   - Build Command: `npm install`
   - Start Command: `npm start`
   - Health Check: `/health`
4. В разделе **Environment** добавь переменную:
   - `Key`: `DATABASE_URL`
   - `Value`: строка из Neon (шаг 1)
5. Нажми **Create / Deploy**. Первая сборка занимает 1–3 минуты.

**Как понять, что всё получилось.** Открой выданный адрес с `/health`, например:

```
https://vk-group-app-server.onrender.com/health
```

Должен вернуться JSON:

```json
{"ok":true,"database":"postgres","seeded":true}
```

Обрати внимание на `"database":"postgres"` — значит сервер работает с облачной базой.
При первом запуске он сам создаст таблицы и зальёт тестовые данные (`"seeded":true`).

## Шаг 4. Подключить приложение к серверу

1. В файле `.env.local` укажи адрес сервера Render:

   ```
   VITE_APP_ID=54822849
   VITE_API_URL=https://vk-group-app-server.onrender.com
   ```

2. Выполни деплой фронтенда (он теперь проходит автоматически, без вопросов):

   ```powershell
   cd C:\Users\Alex\Documents\deepseek-harness\default-workspace\vk-group-app
   npm run deploy
   ```

3. Открой приложение в ВК → **Настройки** → строка «Режим данных».
   Должно быть написано: **«общий сервер — данные видят все одногруппники»**.

4. Проверка вдвоём: на телефоне добавь задание, на компьютере нажми **«Обновить данные»** —
   задание появится. Так же проверь со одногруппником.

## Проверка на твоём компьютере (без облака)

Локальный режим никуда не делся и удобен для отладки:

```powershell
cd server
npm start          # запустится на SQLite-файле, база создастся сама
npm test           # 22 проверки HTTP API
npm run check:postgres   # 16 проверок режима PostgreSQL (на эмуляторе, база не нужна)
```

Чтобы локально поработать именно с облачной базой, задай переменную перед запуском:

```powershell
$env:DATABASE_URL = "строка из Neon"
npm start
```

## Что говорить на защите про этот этап

- Приложение разделено на фронтенд и бэкенд: статика публикуется на хостинге ВКонтакте,
  сервер работает на отдельном Node-хостинге, база данных — управляемый PostgreSQL в облаке.
- Код сервера поддерживает **два режима хранения** и переключается одной переменной окружения:
  SQLite для локальной разработки, PostgreSQL для эксплуатации. Это позволило разрабатывать и
  тестировать приложение без установки сервера БД.
- Слои приложения разделены так, что смена хранилища не затронула ни одного экрана интерфейса:
  изменились только два файла сервера (`database.js` и `db.js`).
- Для проверки логики есть два набора автотестов: 22 HTTP-проверки API и 16 проверок
  SQL-логики PostgreSQL.
