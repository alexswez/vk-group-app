# Публикация приложения: пошаговая инструкция

Инструкция для студента. Всё, что может сделать робот (код, сборка, тесты) — уже сделано.
Здесь только шаги, которые требуют твоего аккаунта ВКонтакте и решения о хостинге.

---

## Из чего состоит публикация

Приложение состоит из **двух частей**, и это важно понимать:

| Часть | Где живёт | Кто публикует |
|---|---|---|
| Фронтенд (интерфейс) | Хостинг ВКонтакте (VK Mini Apps Hosting) | утилита `vk-miniapps-deploy` от твоего имени |
| Бэкенд (общие данные) | Отдельный хостинг для Node.js | ты выбираешь площадку |

⚠️ Два подводных камня, о которых почти нигде не пишут:

1. **VK Hosting хранит только статику** (HTML, JS, CSS). Запустить там Node.js нельзя — сервер
   нужно разместить отдельно.
2. **Внутри ВКонтакте приложение открывается по HTTPS**, поэтому адрес сервера тоже должен быть
   `https://...`. `http://localhost:3000` внутри ВК не заработает: браузер заблокирует
   «смешанный контент».

## Шаг 0. Что нужно от тебя

- **ID приложения** из кабинета разработчика (число).
- Решение, где будет жить сервер (см. шаг 4).
- Готовность один раз войти в ВК в браузере — утилита деплоя попросит подтверждение.

---

## Шаг 1. Вписать ID приложения

**1.1.** Файл `vk-hosting-config.json` — заменить `"app_id": 0` на свой ID (числом, без кавычек):

```json
{
  "static_path": "build",
  "app_id": 12345678,
  "endpoints": { "mobile": "index.html", "mvk": "index.html", "web": "index.html" }
}
```

**1.2.** Файл `.env.local` в корне проекта (создать рядом с `.env.example`):

```
VITE_APP_ID=12345678
VITE_API_URL=https://адрес-твоего-сервера
```

`VITE_APP_ID` нужен кнопке «Поделиться», чтобы формировать ссылку `https://vk.com/app12345678#/tasks`.
`VITE_API_URL` — адрес сервера общих данных.

> Если `VITE_API_URL` не указать, приложение возьмёт `http://localhost:3000` и на опубликованной
> версии переключится в локальный режим (данные будут только у каждого в своём браузере).
> Это не поломка — приложение так и задумано, но общего расписания не получится.

## Шаг 2. Собрать и выгрузить фронтенд

```powershell
npm run deploy
```

Что произойдёт: сначала сборка (`vite build`), потом `vk-miniapps-deploy` загрузит папку `build`
на хостинг ВКонтакте. Утилита спросит подтверждение входа в ВК — это нормально, токен
сохранится в системной папке `~/.config/configstore/@vkontakte/vk-miniapps-deploy.json`.

Для автоматизации (без интерактивного входа) можно передать токен переменной окружения:

```powershell
$env:MINI_APPS_ACCESS_TOKEN = "твой_токен"
npm run deploy
```

Полезно знать: `MINI_APPS_ENVIRONMENT=production` или `dev` — на каком окружении публиковать.
Все production-сборки попадают и на dev-окружение.

**Адрес приложения прописывается автоматически.** В `vk-hosting-config.json` включены флаги
`update_prod: 1` и `update_dev: 1` — утилита сама обновляет адреса в кабинете разработчика
и печатает их в конце:

```
URLs changed for production:
vk.com:  https://prod-app<ID>-<hash>.pages-ac.vk-apps.ru/index.html
```

Руками вставлять ссылку в кабинет **не нужно**.

Флаг `"noprompt": true` в том же файле отключает все вопросы утилиты: деплой проходит
полностью автоматически (`npm run deploy` → сборка → загрузка → готово). Если захочешь
отвечать на вопросы вручную, убери флаг.

Во время деплоя ВКонтакте может попросить **подтвердить публикацию на телефоне** (приходит
уведомление) — это защита платформы от случайной выгрузки новой версии.

## Шаг 3. Проверить, что фронтенд поднялся

1. Открой `https://vk.com/app54822849` под своим аккаунтом.
   Прямая ссылка на файлы приложения (проверка без ВКонтакте):
   `https://prod-app54822849-42d4f1518ef3.pages-ac.vk-apps.ru/index.html`
2. Должны появиться три вкладки. Если увидел белый экран — нужна консоль: в мобильном
   приложении ВК её нет, поэтому добавь в `.env.local` строку `VITE_DEBUG=1`, выполни
   `npm run deploy` заново и открой приложение — внизу появится кнопка консоли Eruda
   с текстом ошибки. После отладки строку лучше убрать.

## Шаг 4. Разместить сервер (нужно выбрать)

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Локально на своём компьютере** | ноль затрат, всё под контролем, идеально для защиты | работает, только пока компьютер включён и находится в той же сети; для зрителей с телефона нужен туннель |
| **Бесплатный хостинг Node** (Render, Railway, Fly.io) | доступен из интернета по HTTPS, можно показать всей группе | нужна регистрация; на бесплатных тарифах приложение «засыпает» и диск часто **непостоянный** — файл SQLite может обнуляться |
| **Бесплатный PostgreSQL + небольшой хостинг** | данные не теряются, честная клиент-серверная архитектура | дольше настраивать, код сервера нужно переключить на пакет `pg` |

**Рекомендация:** для защиты диплома/курсовой — локальный запуск (всё быстро и стабильно).
Если хочется, чтобы приложение работало у всей группы круглосуточно — бесплатный хостинг Node
плюс переход на PostgreSQL (в проекте для этого всё готово: схема таблиц и запросы универсальны).

Docker-образ для сервера уже подготовлен: `server/Dockerfile`.
Команды для локальной проверки образа:

```powershell
cd server
docker build -t vk-group-app-server .
docker run -p 3000:3000 -v vk-data:/app/data vk-group-app-server
```

## Шаг 5. Проверить на телефоне и в беседе группы

1. Открой приложение в мобильном приложении ВКонтакте.
2. Добавь задание — оно должно появиться и на компьютере (значит, общее хранилище работает).
3. Отправь расписание в беседу: вкладка «Расписание» → кнопка **«Поделиться расписанием»** →
   выбери беседу группы. Получатель откроет приложение сразу на расписании.
4. Прикрепить приложение к сообщению можно и вручную: в мобильном приложении в поле ввода
   сообщения нажать скрепку → «Мини-приложения» → выбрать наше.

> **Честная оговорка про чат.** Мини-приложение не может само писать сообщения в беседу —
> для этого нужен **бот** (сообщество ВКонтакте + токен + сервер, который слушает события).
> Это отдельная работа, и её можно сделать следующим этапом: бот раз в день публикует
> расписание в беседу. Кнопка «Поделиться» закрывает задачу «посмотреть из чата» без бота.

## Если что-то пошло не так

| Ошибка | Причина и решение |
|---|---|
| `User authorization failed: invalid session` | устарел токен деплоя. Удалить файл `~/.config/configstore/@vkontakte/vk-miniapps-deploy.json` и запустить `npm run deploy` снова |
| Приложение не открывается по ссылке `vk.com/app<ID>` | проверь, что деплой прошёл (в конце вывода должны быть строки `URLs changed for production`); адрес прописывается флагами `update_prod`/`update_dev`. Также убедись, что приложение доступно в кабинете разработчика |
| Данные не сохраняются между устройствами | не задан `VITE_API_URL` или сервер недоступен; в «Настройках» приложения посмотри строку «Режим данных» |
| В консоли `Mixed Content` или `CORS` | адрес сервера не `https` (внутри ВК обязателен HTTPS) |
| `vk-tunnel` не подключается | сервис VK Tunnel недоступен с 2 октября 2025 года (официальное уведомление VK); для проверки внутри ВК используем деплой или сторонний туннель (`cloudflared`, `ngrok`) |

## Хостинг вне ВКонтакте (если модерация не нужна)

Приложение — обычный статический сайт: папка `build/` (8 файлов, 1,6 МБ). Ему не нужен сервер:
данные лежат в облаке Supabase, маршрутизация хеш-ная (`#/tasks`), пути к файлам относительные.
Поэтому сборку можно положить на любой бесплатный статический хостинг, и приложение откроется
у любого человека по ссылке — без модерации ВКонтакте и без администраторов.

### Что меняется по сравнению с версией в ВК

| Работает так же | Работает иначе |
|---|---|
| расписание, задания, материалы, редактирование | имя и аватар в «Настройках» не показываются (нет VK Bridge) |
| общие данные (облако Supabase) | личные настройки хранятся в браузере, а не в VK Storage |
| сохранение файлов в общее хранилище | кнопка «Поделиться» копирует ссылку в буфер, а не открывает диалог ВК |

Код приложения к этому готов: отсутствие ВКонтакте обрабатывается, приложение переключается
на запасной режим (см. `src/storage/userPrefs.ts` и `src/utils/share.ts`).

### Вариант 1. Surge (одна команда)

```powershell
npm run deploy:surge
```

При первом запуске Surge спросит почту и пароль — так создаётся бесплатный аккаунт.
Адрес сайта задан в `package.json` в команде `deploy:surge` (по умолчанию `ispsv301.surge.sh`).
Обновление сайта — та же команда.

### Вариант 2. Netlify Drop (без аккаунта, без пароля)

1. Выполнить `npm run build`.
2. Открыть https://app.netlify.com/drop
3. Перетащить в окно браузера папку `build` целиком.
4. Получить ссылку вида `https://<случайное-имя>.netlify.app` и отправить её группе.
   Чтобы сайт не пропал со временем, ссылку можно «присвоить» бесплатным аккаунтом.

### Вариант 3. GitHub Pages / Cloudflare Pages / Vercel

Все три требуют бесплатный аккаунт; для GitHub Pages ещё и выкладывания кода в репозиторий
(в `vite.config.ts` при этом нужен `base: './'`).

### Важно: приватность

Адрес сайта публичный: любой, кто знает ссылку, увидит данные группы и сможет их менять.
Для учебной группы это и нужно, но не добавляйте в приложение ничего личного.
Ключ Supabase `publishable` попадает в сборку — это нормально, он и предназначен для браузера.

### Проверенный факт про Surge (14.10.2026)

Публикация на Surge с этого компьютера **не работает для нашей сборки**: сервис отклоняет
загрузку файлов больше ~12 КБ (проверено десятками попыток: текст 400 КБ проходит, если
сжимается почти в ноль, а несжимаемые данные уже с 16 КБ отклоняются). Причина — ограничение
сетевого канала, а не приложения: публикация в ВК загружает те же 1,6 МБ нормально.
Если понадобится Surge, публиковать нужно с другого компьютера или из браузера.

### Вариант 4. Netlify через API (одна команда, нужен токен)

1. Создать бесплатный аккаунт на https://app.netlify.com (почта + пароль).
2. Открыть **User settings → Applications → Personal access tokens → New access token**,
   скопировать токен (показывается один раз).
3. Положить токен в `.env.local` (файл уже в `.gitignore`, в репозиторий не попадёт):

   ```
   NETLIFY_TOKEN=вставь_токен_сюда
   ```

4. Выполнить `npm run deploy:netlify` — скрипт соберёт сайт, упакует в архив, создаст сайт
   `ispsv301.netlify.app` (если его ещё нет) и опубликует версию.
5. Повторный запуск обновляет тот же сайт.

Скрипт: [scripts/deploy-netlify.mjs](../scripts/deploy-netlify.mjs).

**Опубликовано:** https://ispsv301.netlify.app — проверено: все 8 файлов сборки на сервере
совпадают с локальными по SHA1. Обновление сайта — одна команда `npm run deploy:netlify`.

⚠️ Подводный камень, на который мы наткнулись: **не публикуйте сборку zip-архивом**.
`Compress-Archive` в PowerShell и .NET пишут пути внутри архива с обратными слэшами
(`assets\index.js`), а `tar` добавляет префикс `./`. Netlify раскладывает такие файлы
не по адресам, и вложенные файлы отдают 404 (при этом главная страница открывается —
легко не заметить). Скрипт [scripts/deploy-netlify.mjs](../scripts/deploy-netlify.mjs)
поэтому загружает файлы по одному через API Netlify «по отпечаткам SHA1» — это надёжно и
не зависит от особенностей упаковки архивов в Windows.

## GitHub Pages (постоянный адрес, доступен из России)

Проверено с рабочего компьютера: GitHub отдаёт файлы быстро (126 мс), в отличие от Netlify,
который из этой сети недоступен совсем (0 успешных загрузок из 3 попыток, таймаут 20 с).

### Что нужно один раз

1. Зарегистрироваться на https://github.com (нужна подтверждённая почта).
2. Создать **публичный** репозиторий, например `vk-group-app` (без README и .gitignore — пустой).
3. Добавить ключ для публикации: **Settings → SSH and GPG keys → New SSH key**,
   вставить содержимое файла `~/.ssh/id_ed25519_github.pub`
   (это публичная часть ключа, секрета в ней нет).
4. Включить страницы: **Settings → Pages → Source: Deploy from a branch →
   Branch: gh-pages, папка / (root)**. Это делается после первой публикации,
   потому что ветка появляется только после неё.

### Публикация и обновление

```powershell
npm run deploy:github -- <логин>/vk-group-app --with-source
```

Скрипт соберёт сайт, отправит содержимое `build/` в ветку `gh-pages` (плюс `.nojekyll`,
чтобы GitHub не фильтровал файлы), а с флагом `--with-source` ещё и загрузит исходный код
в ветку `main`. Через минуту сайт обновится по адресу
`https://<логин>.github.io/vk-group-app/`.

Почему это работает без настройки сервера: пути в сборке относительные (`./assets/...`),
а маршрутизация в приложении хеш-ная (`#/tasks`), поэтому подкаталог `/vk-group-app/`
и отсутствие правил перенаправления не мешают.

**Проверка перед публикацией:** в репозиторий не попадают `.env.local` (там ключи) и
`vk-hosting-config.json` (там только ID приложения) — я проверял отдельно, значений токенов
в файлах под контролем версий нет.
