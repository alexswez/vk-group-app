# «Расписание группы» — VK Mini App

Мини-приложение для учебной группы: расписание пар и список заданий (домашки, лабораторные,
курсовые) с общим хранилищем, чтобы все одногруппники видели одни и те же данные.

**Стек:** React 18 + TypeScript + VKUI 8 + VK Bridge + vk-mini-apps-router, сборка — Vite 8.
Сервер: Node.js + Express 5, база данных в двух режимах: SQLite (встроенный модуль `node:sqlite`)
для локальной разработки и **PostgreSQL** для публикации. Режим выбирается переменной окружения
`DATABASE_URL` — подробности в [POSTGRES.md](POSTGRES.md).

---

## Что уже умеет приложение

- **Расписание** — выбор дня недели, пары с временем, аудиторией, преподавателем и видом занятия
  (лекция / практика / лабораторная), подсветка «сейчас идёт», учёт чётности недели.
- **Задания** — фильтры (активные / просроченные / сданные / все), фильтр по предмету,
  сортировка по сроку сдачи, статусы «не начато / в работе / сдано», подсветка горящих сроков.
- **Добавление и правка** — задания и пары создаются, изменяются и удаляются прямо из приложения
  (с подтверждением удаления), есть валидация полей.
- **Настройки** — название группы, подгруппа, показ прошедших пар, сброс к тестовым данным,
  индикатор режима работы (общий сервер или локально).
- **Общие данные** — всё хранится на сервере, поэтому изменения видны всей группе.
- **Поделиться в беседу** — кнопка формирует ссылку вида `https://vk.com/app<ID>#/tasks`
  и открывает системное окно «Поделиться» ВКонтакте (`VKWebAppShare`). Получатель открывает
  приложение сразу на нужной вкладке — это и есть «просмотр из чата».

> Про чат честно: мини-приложение нельзя встроить в беседу как сообщение от его имени.
> Работают два пути — поделиться ссылкой (кнопка выше) или завести бота, который сам пишет
> в чат. Второй вариант требует отдельного сервиса и токена сообщества.

## Как запустить

Нужны **два терминала**.

**Терминал 1 — сервер (общее хранилище):**

```powershell
cd server
npm install
npm start
```

Поднимется на http://localhost:3000, база создастся сама и наполнится тестовыми данными.

**Терминал 2 — приложение:**

```powershell
npm install
npm start
```

Откройте http://localhost:5173

**Проверка API (когда сервер запущен):**

```powershell
cd server
npm test
```

21 проверка: CRUD заданий и пар, валидация, кириллица, сброс данных.

Плюс проверка режима PostgreSQL — настоящая база для неё не нужна, работает эмулятор:

```powershell
npm run check:postgres
```

16 проверок: создание таблиц, подстановка параметров `$1`, upsert, удаление, сброс.

## Проверки качества (всё одной командой)

| Команда | Что проверяет |
|---|---|
| `npm run check` | типы + линтер + тесты фронтенда — быстрая проверка перед коммитом |
| `npm run lint` | ESLint с запретом любых предупреждений |
| `npm test` | **12 тестов фронтенда** (утилиты дат и цветов) на встроенном тест-раннере Node |
| `cd server && npm test` | **21 проверка HTTP API** |
| `cd server && npm run check:postgres` | **16 проверок режима PostgreSQL** (на эмуляторе) |

Итого **49 автоматических проверок**. Тесты фронтенда не требуют дополнительных библиотек:
Node 24 умеет запускать TypeScript напрямую, а `node:test` встроен в Node.js.

## Ключевые решения (то, о чём спрашивают на защите)

**1. Почему общие данные не в VK Storage.**
В VK Storage переменные привязаны к пользователю: в схеме VK API у методов `storage.get` и
`storage.set` есть параметр `user_id`. Значит, из клиента каждый пользователь видит **свою**
копию, и задание, добавленное старостой, не увидели бы остальные. Поэтому общие данные
(расписание, задания) живут на нашем сервере, а в VK Storage хранятся только **личные**
настройки: подгруппа и показ прошедших пар.

**2. Одна кодовая база — два хранилища.**
Сервер поддерживает PostgreSQL (если задана переменная `DATABASE_URL`) и SQLite (если нет).
Это позволило разрабатывать и полностью тестировать приложение без установки сервера БД, а для
эксплуатации использовать управляемый PostgreSQL в облаке. Переключение — одна переменная
окружения: схема таблиц и все маршруты API общие. Подробности — в [POSTGRES.md](POSTGRES.md).

**3. Почему `node:sqlite`, а не `better-sqlite3`.**
Встроен в Node.js 22.5+ — не требует компиляции нативных модулей, проект запускается
«из коробки» на любой машине.

**4. Слой хранения (storage layer).**
Экраны не знают, откуда берутся данные: они вызывают `loadGroupData()` и методы изменения.
Внутри спрятаны три источника — API сервера, VK Storage и localStorage. Благодаря этому
приложение не падает, если сервер выключен: оно автоматически переходит в локальный режим.

**5. Оптимистичное обновление.**
Интерфейс обновляется сразу, не дожидаясь ответа сети, а затем состояние заменяется
ответом сервера. Пользователь не чувствует задержку, а данные остаются корректными.

**6. Типобезопасность.**
Все типы (`Subject`, `Lesson`, `Task`, `GroupData`) описаны в одном файле `src/types.ts`
и используются и фронтендом, и (по структуре) сервером. Ошибки в названиях полей ловит
компилятор TypeScript ещё до запуска — это доказано на практике: при разработке `tsc`
нашёл 8 несовпадений с API VKUI 8.

## Что осталось сделать

1. Создать приложение в кабинете разработчика VK, указать его ID в `vk-hosting-config.json`
   и в `.env.local` (`VITE_APP_ID=...`) — от этого зависит правильная ссылка в кнопке «Поделиться».
2. Задеплоить фронтенд на VK Mini Apps Hosting (`npm run deploy`).
3. Разместить сервер в интернете (VK Hosting хранит только статику) и прописать его адрес
   в `VITE_API_URL`.
4. Проверить приложение на телефоне и прикрепить его в беседу группы.
